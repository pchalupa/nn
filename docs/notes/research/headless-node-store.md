# NN store in headless Node.js processes

Researched 2026-11-06. Inspected working tree at HEAD `00486d7d39623941e2594c28aeaef4740a703646`, including existing uncommitted React integration changes. **Source** below means implemented control flow; **inference** means a consequence or integration recommendation. Source review was independent of the main investigation's runtime probes, whose results are recorded separately below.

## Assessment

**The core store is suitable as an in-memory state container for a headless program.** It constructs synchronously, supports typed reads and updates, and exposes subscriptions without React, a DOM, persistence, or a network connection. Its constructor only creates `State` and connects its delegate to two observables. React is a separate consumer. [Store, lines 8–23](../../../packages/store/src/store.ts#L8-L23), [State, lines 32–70](../../../packages/store/src/state.ts#L32-L70), [dependencies](../../../packages/store/package.json#L24-L30).

**A durable, synchronized worker needs application-owned lifecycle and work coordination.** The existing engines provide transport hooks and connection state, but no delivery acknowledgement, outgoing drain, durable job queue, or exclusive work claims. A new Node wrapper is not required for basic use; selector watches and a Node-specific factory remain proposed conveniences. [SyncEngine, lines 14–81](../../../packages/sync-engine/src/sync-engine.ts#L14-L81), [Node client design, lines 70–104](../../superpowers/specs/2026-11-05-node-client-design.md#L70-L104).

**Execution recommendation:** keep the repository's source-first exports and consume them from an ESM app with `tsx`, or bundle all required `@nn/*` dependencies. Compiling only the application entry point can leave unsupported dependency source for Node to load. Node's official documentation explains that strip-only execution does not transform parameter properties or enums, requires explicit file extensions, and refuses TypeScript under `node_modules`. The probes establish the working loader/bundle paths here, not arbitrary installed-package layouts. [Node type stripping](https://nodejs.org/api/typescript.html#type-stripping), [type stripping in dependencies](https://nodejs.org/api/typescript.html#type-stripping-in-dependencies).

**Node-only type checking:** a core-only consumer passed with `lib: ES2022`, Node types, and bundler module resolution. Adding broadcast sync failed with `TS2315: Type 'MessageEvent' is not generic` at its `MessageEvent<unknown>` annotation. Runtime compatibility therefore does not yet mean the adapter compiles with a DOM-free TypeScript configuration. [Broadcast callback](../../../packages/broadcast-sync/src/broadcast-sync.ts#L19). On the tested Node launch, `fetch`, `crypto`, `AbortController`, and `BroadcastChannel` were available; `EventSource` and `indexedDB` were undefined. SSE needs a supplied compatible global implementation or verified deployment support.

The React example is not a reusable headless entry point: its module attaches IndexedDB and broadcast sync immediately, reads `location.origin`, and registers global `online` and `document.visibilitychange` listeners. Its schema is currently private to that module. **Inference:** share the schema through a platform-neutral module when building a browser/Node pair. [Example store, lines 43–63](../../../apps/example-react/src/store.ts#L43-L63).

## Reads, updates, and subscriptions

- **Source:** `state.read()` returns revision-cached snapshots. Projected object/array nodes are frozen, and unchanged entity revisions reuse their snapshot. Draft projection creates a separate tree. Existing tests check frozen snapshots, stable references, independent drafts, and retained-draft edits. [View, lines 21–39](../../../packages/store/src/projectors/view.ts#L21-L39), [Projector, lines 16–41](../../../packages/store/src/projectors/projector.ts#L16-L41), [state tests, lines 45–130](../../../packages/store/src/state.test.ts#L45-L130), [retained drafts test](../../../packages/store/src/state.test.ts#L312-L327).
- **Source:** `state.update(recipe)` runs the recipe synchronously, ignores its return value, then reconciles. A recipe that throws before reconciliation publishes nothing. Reconciliation itself can partially apply before throwing; `commit` still notifies in `finally`. This is not rollback. Both failure cases have explicit tests. [State, lines 51–81](../../../packages/store/src/state.ts#L51-L81), [store tests, lines 144–192](../../../packages/store/src/store.test.ts#L144-L192).
- **Inference:** do async I/O outside the recipe, then apply the result in a fresh synchronous update. An async recipe is not awaited: only its synchronous prefix is reconciled, later draft edits are not committed, and a rejected returned promise is not handled. Re-check current state after I/O if other work may have changed the input. [State, lines 51–58](../../../packages/store/src/state.ts#L51-L58).
- **Source:** subscriptions are synchronous and non-replaying. `changes` receives the changed top-level entities before `updates` fires without arguments. A normal multi-field recipe produces one commit notification; no-ops do not notify. Use `state.read()` for an initial value, then subscribe for invalidation. [Store, lines 9–20](../../../packages/store/src/store.ts#L9-L20), [Observable, lines 8–20](../../../packages/observable/src/observable.ts#L8-L20), [notification tests](../../../packages/store/src/store.test.ts#L46-L115).
- **Source and inference:** `Observable` traverses a live `Set`, not a snapshot, and catches no exceptions. The same callback subscribed twice is stored once. A throwing observer stops later observers; a throwing `changes` observer also prevents `updates` and may prevent later engines from seeing that commit. Adding/removing observers during traversal follows live-Set semantics. Async listeners are not awaited or rejection-managed. [Observable](../../../packages/observable/src/observable.ts#L5-L20), [deduplication test](../../../packages/observable/src/observable.test.ts#L54-L63).
- **Source and inference:** listener-triggered updates notify recursively; there is no coalescing scheduler, selector equality, recursion limit, or backpressure. Keep expensive work outside notification callbacks and own concurrency explicitly. Draft creation walks the state tree, while sync encodes whole changed root fields, so large collections deserve workload-specific measurement. [Reentrant update test](../../../packages/store/src/state.test.ts#L473-L494), [draft projection](../../../packages/store/src/projectors/draft.ts#L5-L8), [recursive projection](../../../packages/store/src/projectors/projector.ts#L12-L38), [sync send loop](../../../packages/sync-engine/src/sync-engine.ts#L49-L53).

## Lifecycle, readiness, and shutdown

**Source:** each engine owns a public `session` with readable state/booleans and a `changes` observable. `attach()` starts connection work and returns the engine immediately. `connect`, `retry`, `reconnect`, and `detach` return `void`; none provides a completion promise. `Connected` follows successful open and sequential initial pulls/merges, but outgoing sends are started without waiting. Observe `session.changes` and inspect `session.state` when readiness matters; do not replace its delegate, which the engine uses internally. [Session, lines 28–77 and 112–119](../../../packages/sync-engine/src/session.ts#L28-L77), [engine initialization](../../../packages/sync-engine/src/sync-engine.ts#L20-L59).

**Source:** SSE open resolves only after the first successfully processed message, not on the connection's open event. A server that connects without sending an initial message can leave the session connecting indefinitely. Later `EventSource` errors drop the session only when `readyState === CLOSED`; transient reconnecting states are not reflected as disconnected. There is no library timeout or retry timer. Explicit `session.retry()` works from disconnected, and the tests explicitly assert that editing the store does **not** retry. [EventStream, lines 15–43](../../../packages/sse-sync/src/event-stream.ts#L15-L43), [session transitions](../../../packages/sync-engine/src/session.ts#L130-L152), [SSE retry tests, lines 164–199](../../../packages/sse-sync/src/sse-sync.test.ts#L164-L199).

**Source:** `session.detach()` is terminal and idempotent. It aborts the open signal, unsubscribes the engine from store changes, and calls its transport close. Existing tests cover detach during open/pull and after connection. Core `Store` itself owns no timer/socket and has no disposal method; callers own subscription unsubscribe functions and attached engines. [Session, lines 122–134](../../../packages/sync-engine/src/session.ts#L122-L134), [engine close](../../../packages/sync-engine/src/sync-engine.ts#L55-L58), [detach tests](../../../packages/sync-engine/src/sync-engine.test.ts#L258-L342).

**Limitation:** detach is not a flush or cancellation guarantee for pending writes. `push` receives no abort signal, and SSE POSTs have no signal. Concurrent sends are allowed, including several versions of the same field while an earlier send is pending. Push rejection is reported through the optional engine delegate, but is not retried or rethrown to the originating update. **Inference:** a short-lived CLI cannot use `update(); detach(); exit` as proof of delivery; a long-lived worker must own error handling and shutdown policy. [Engine, lines 62–80](../../../packages/sync-engine/src/sync-engine.ts#L62-L80), [SSE POST](../../../packages/sse-sync/src/sse-sync.ts#L42-L49), [overlapping-send and failure tests](../../../packages/sync-engine/src/sync-engine.test.ts#L189-L239).

## Persistence and replicated-state limits

**Source:** the store retains data only in memory unless an adapter saves it. `state.encode()` preserves entity keys, kinds, and timestamps; `Codec.decode()` plus `state.merge(name, entity)` provides the existing restore mechanism per root field. Saving only `state.read()` loses that metadata. The persistence-format tests check timestamp-preserving round trips. A custom Node engine can implement `open/close/pull/push`, but no filesystem or SQLite engine exists in the inspected package sources. [State, lines 60–70](../../../packages/store/src/state.ts#L60-L70), [Codec](../../../packages/entities/src/codec.ts#L4-L16), [persistence tests](../../../packages/store/src/store.test.ts#L205-L244), [extension interface](../../../packages/sync-engine/src/sync-engine.ts#L62-L65), [Node design's future adapters](../../superpowers/specs/2026-11-05-node-client-design.md#L165).

**Source and inference:** initial pulls and received batches merge fields separately. Observers can see intermediate cross-field state, and later failure does not undo earlier merges. Incoming changes are sent back when they change the local store. Broadcast sync has no pull or request/reply bootstrap: it announces the joining store's own fields, but does not explicitly request existing peers' state. Its `entries` cache is written but never replayed. Do not treat attachment as proof that a new empty peer has received existing data. [SyncEngine, lines 26–33, 49–53, 67–72](../../../packages/sync-engine/src/sync-engine.ts#L26-L33), [echo test](../../../packages/sync-engine/src/sync-engine.test.ts#L297-L305), [BroadcastSync, lines 6–40](../../../packages/broadcast-sync/src/broadcast-sync.ts#L6-L40).

Two implementation limits matter independently of Node:

- `RGA` is explicitly a temporary list implementation. Merge unions rows by identity, removal has no tombstone, and local reorder is ignored by a current test. **Inference:** another replica can restore a removed row; list order is not a complete replicated ordering contract. [RGA, lines 6–8 and 54–81](../../../packages/entities/src/rga.ts#L54-L81), [reorder test](../../../packages/store/src/state.test.ts#L228-L246).
- `Time` has one static clock/replica ID per loaded module instance. Decoding timestamps does not advance that shared clock; register merge compares and copies timestamps without observing them into the clock. **Inference:** receiving a future timestamp does not guarantee the next local edit will outrank it on another replica. Replica IDs are conflict-ordering identifiers, not user identities. [Time, lines 10–34 and 92–112](../../../packages/time/src/time.ts#L92-L112), [register merge](../../../packages/entities/src/lww-register.ts#L19-L40).

## SSR and multi-tenant processes

**Source:** each `Store` constructs its own state, observables, projection caches, and change set. No singleton store is built by the core module. The React adapter passes the same `state.read` getter as both client and server snapshot getter. There is no automatic server/client snapshot transfer or request-scoped store registry. [Store constructor](../../../packages/store/src/store.ts#L9-L21), [State fields](../../../packages/store/src/state.ts#L24-L42), [React snapshot wiring](../../../packages/react/src/index.ts#L21-L28).

**Inference:** create stores per request or tenant when their data must remain separate, and hydrate server/client stores consistently yourself. Do not reuse the example's module-level store for unrelated requests. Use distinct broadcast channel/database names and separately scoped remote endpoints for distinct datasets: both local adapters default to `nn-default`, and SSE only takes a URL. An engine is bound to one store; its receive path filters schema field names, not tenant ownership. [Broadcast default](../../../packages/broadcast-sync/src/broadcast-sync.ts#L35-L40), [IndexedDB default](../../../packages/indexdb-sync/src/index-db-sync.ts#L38-L43), [SSE constructor and factory](../../../packages/sse-sync/src/sse-sync.ts#L12-L18), [receive path](../../../packages/sync-engine/src/sync-engine.ts#L67-L72).

**Limitation:** schema typing and encoded-entity checks are not an authorization or complete runtime validation boundary. Register reconciliation accepts an arbitrary value, register decoding checks timestamp metadata but not the schema's value type, and state merge checks the field/key rather than validating the incoming entity against the declared schema. SSE exposes no headers, credentials, or injected-fetch options. Applications must supply their own request isolation, validation, and authentication integration. [RegisterStrategy](../../../packages/store/src/reconciliation/register-strategy.ts#L10-L18), [register decoding](../../../packages/entities/src/lww-register.ts#L51-L72), [State.merge](../../../packages/store/src/state.ts#L60-L65), [SSE request construction](../../../packages/sse-sync/src/sse-sync.ts#L42-L47).

The store and engine READMEs currently contain only headings. Existing tests give useful evidence for core behavior, merge semantics, overlapping pushes, and detach cleanup. IndexedDB tests use a fake backend; SSE tests replace browser-shaped globals. These are not end-to-end process, durability, SSR-isolation, or network-compatibility checks. ADR-16 describes `session` as protected, while the current class makes it public.
